Учебный пример старинной 3D-графики — ZX Spectrum Elite
Дата первоначального разбора — 3 ноября 2026 года.

1. Цель и принятые решения

Проект показывает, как ZX Spectrum Elite выбирает видимые рёбра и рисует
каждый пиксель отрезка. Основание для сравнения — оригинальные инструкции Z80
и таблицы моделей. Учебный просмотрщик написан на Python и Pygame.
В пиксельном режиме Pygame отвечает за окно, ввод и вывод готового bitmap.
Выбор пикселей, их запись и проверки видимости выполняет код проекта.

2. Исходники и данные

Публичная ревизия с исходниками демо и инструкциями по запуску
https://github.com/nslmike/zx-elite-gfx/tree/7a290d34ae321c3429354cfbc0e0eae2cd4b46ba/elite_pygame_lab

Для свежей рабочей копии подготовьте таблицы моделей из кассеты, снимка памяти
и исходников Elite Legend. Ссылки на источники, команда подготовки и SHA-256
приведены в elite_pygame_lab/reference_data/README.md.

3. С чего начать

Откройте elite_pygame_lab/README.md для запуска просмотрщика и выбора режима.
Пиксельный цикл разбирается в elite_pygame_lab/elite_lab/raster.py, запись
битов — в framebuffer.py в том же каталоге. Проверенные ракурсы и результаты
сверки с листингом приведены в FINDINGS.md.

Разделы 5–10 ниже описывают первоначальную версию с одной Cobra Mk III.
Обработку клиппинга и результаты по всему каталогу описывает текущий README.

4. Запуск и зависимости

Рекомендуемое/проверенное окружение: Python 3.12, pygame==2.6.1.
Исходники используют синтаксис Python 3.10+.
SkoolKit==10.1 нужен только для отдельного differential verification,
не для рабочего просмотрщика.

После подготовки локальных данных откройте каталог elite_pygame_lab и запустите демо.

    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python -m elite_lab

Сразу пошаговая линия:

    python -m elite_lab --mode line

Проверка по настоящим машинным инструкциям:

    python -m pip install -r requirements-verify.txt
    python tools/verify_reference.py --lines 1000 --poses 128 --output validation.json

Снимки UI без окна:

    python -m elite_lab --headless --screenshot previews/ship.png
    python -m elite_lab --headless --mode line --screenshot previews/line.png

5. Возможности первоначальной версии

- Cobra Mk III по исходным таблицам: 28 вершин, 38 рёбер, 13 граней.
- Вращение, крен, управление расстоянием, выбор ребра.
- Для ребра показаны связанные грани, флаги, порог и причина рисования/пропуска.
- Enter переносит выбранное видимое ребро во вкладку «Шаги линии».
- Во второй вкладке ручной пиксельный цикл можно проходить по шагам.
- Видны x/y, накопитель E до/после, carry, адрес Spectrum, маска и увеличенная
  сетка вокруг последнего записанного пикселя.
- Концы линии двигаются мышью; P переключает учебные примеры.

Управление:
Tab или 1/2 — вкладки; стрелки в корабле — вращение; Q/E — крен;
колесо или +/- — расстояние; [/] — выбор ребра; Enter — пиксели ребра;
стрелки в линии — один шаг вперёд/назад; Space — анимация;
R/Home — начало; End — весь отрезок; P — примеры; G — сетка; Esc — выход.

6. Карта кода

elite_lab/model.py
  Исходные байты Cobra и их расшифровка в Vertex/Edge/Face.

elite_lab/arithmetic.py
  Читаемые sign-magnitude операции, отдельный знак нуля, умножения через
  разность квадратов/старшие байты, исходное приближённое деление.

elite_lab/renderer.py
  classify_faces, project_vertices, select_edges, render_geometry.
  Возвращает GeometryTrace: distance, face_flags, projected, edge_decisions.

elite_lab/raster.py
  trace_line(start,end) → LineTrace с последовательностью PixelStep.
  Ручная растеризация, slope_increment, исходные адреса и битовые маски.
  start/end — ProjectedVertex(xmag,ymag,flags), как 3 байта таблицы $A8FA.

elite_lab/framebuffer.py
  Обычный построчный monochrome bitmap 256x128; ручной set_pixel через OR.
  Перестановка адресов Spectrum вынесена отдельно, сами пиксели сохраняются.

elite_lab/controls.py
  Современное задание позы через yaw/pitch/roll. Тригонометрия только в UI:
  она выдаёт квантованные nose/roof, а не подменяет математику рендера.

elite_lab/viewer.py
  Две вкладки, ввод, инспекторы и воспроизведение уже вычисленных шагов.

elite_lab/reference.py
  Независимый эталон: исполняет оригинальные Z80-инструкции через SkoolKit.

reference_data/renderer_blocks.json
  Минимальные оригинальные блоки, их происхождение и SHA-256. Всего 4439
  исходных байт: модель, нужные процедуры и таблица квадратов. Полной игры нет.

tools/verify_reference.py, validation.json
  Воспроизводимая дифференциальная проверка и уже полученный отчёт.

7. Подтверждённая проверка

Первая сверка одной Cobra завершилась со status=passed при seed=1985.
2056 линий / 133675 записей пикселей.
180 поз Cobra / 18634 записи пикселей.
Актуальный отчёт по всему каталогу находится в elite_pygame_lab/validation.json.

Совпали с исполнением оригинальных инструкций:
- адреса и маски записи каждого пикселя;
- значение восьмибитного накопителя перед записью;
- флаги граней;
- три байта каждой вычисленной проекции, включая знак нуля;
- набор/порядок выбранных рёбер;
- последовательность пикселей каждого ребра;
- ВСЕ 4096 байт итогового framebuffer.

Это конечные differential tests заявленного диапазона, не формальное
доказательство эквивалентности на всех возможных входах.
Код и модель fixture побайтно сверены с TAP из того же закреплённого репозитория.
Таблица квадратов взята из снимка памяти после её инициализации.
Проверены переход корабль→линия, stepping, presets, drag, animation, zoom limits,
resize через SDL dummy. Нативный GUI на macOS в исходной среде не запускался.

8. Ограничения первоначальной версии

- Только фронтальный вид.
- Центр корабля (0,0,z), 768 <= z <= 6000.
- Это обычная ветвь $AB73; близкая повышенной точности $AA2B не перенесена.
- Дальняя замена корабля точкой не вызывается и не перенесена.
- Только внутренний путь линии: xmag<128, ymag<64 у обоих концов.
  В абсолютных экранных координатах X=0..254, Y=0..126.
- Внешние ветви viewport clipping $B044 ещё не перенесены.
  Неподдержанные входы явно дают ValueError. Стандартного клиппера вместо
  оригинального не добавляли.
- Текущая Cobra при разрешённых позах укладывается в этот диапазон.

9. Особенности алгоритма, которые обязательно сохранить

Ручной пиксельный цикл:
- E начинается с 128.
- slope вычисляется исходным восьмибитным делением.
- После записи пикселя (если это не последний): total=E+slope,
  carry=total>=256, E=total&255.
- По ведущей оси шаг всегда, по второй только при carry.
- Ведущая ось выбирается сравнением dx>>1 и dy>>1. Поэтому dx=4,dy=5
  выбирает X; это намеренно сохранённое поведение оригинала.
- Записей max(major_delta,1); конечная точка обычно исключена.
- При равных приращениях slope=255, не 256.
- Последний пиксель возвращается ДО изменения E.
- Совпавшие концы рисуют один пиксель.

Сохранить исходные нормали (не пересчитывать «правильные»), специальный индекс
грани 15, дальностные пороги, порядок округлений и знак-модуль с отрицательным
нулём. Обычный a*b не всегда эквивалентен исходному табличному умножению.
Не заменять ручную линию pygame.draw.line/aaline, generic Bresenham или GPU.

В изученном оригинальном рендерере НЕТ общего определения, какие части ребра
закрыты другими гранями корабля. После теста двух face flags ребро идёт одним
отрезком на экранное рисование. Не добавлять z-buffer, скрытие частичных
перекрытий или полигональную маску под видом реконструкции оригинала.

Геометрически back-face проверки достаточно для выпуклого корпуса, но нельзя
утверждать, что все реальные модели Elite строго выпуклы: даже у Cobra есть
небольшие отклонения. Флаг обращённости грани не означает общий occlusion test.

10. Первичные источники и адреса

Закреплённый листинг:
https://github.com/Rasmus-M/elite-skoolkit/blob/66ee08efb2aceddbd67d5003c28fed3477b34850/src/elite.skool

Репозиторий: https://github.com/Rasmus-M/elite-skoolkit
Commit: 66ee08efb2aceddbd67d5003c28fed3477b34850

$64BE — вершины Cobra; $6566 — рёбра; $65FE — нормали.
$AECC / $AF22 — подготовка ориентации.
$BCD4 / $BD5F — проверка граней.
$A9C9 / $ACA2 — выбор и проекция вершин.
$AB73 / $ABC0 — обычный путь поворота; $AC69 — деление/проекция.
$AE01 — выбор рёбер.
$B044 — общий вход линии/клиппера; перенесена внутренняя ветвь.
$B3A7 — выбор ведущей оси; $B2FE / $AC8B — деление для slope.
$B434 / $B464 / $B485 / $B4B1 — пиксельные циклы.

Рекомендуемый порядок продолжения: изучить проект → нативно запустить →
проверить управление → исправить реальные проблемы среды/UI → кратко сообщить
результат и оставшиеся ограничения. Для изменений численного ядра повторять
дифференциальную проверку по оригиналу и не скрывать расхождения.
