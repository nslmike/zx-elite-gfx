# Elite: пиксель за пикселем

Учебный просмотрщик **19 каркасных объектов кассетной ZX Spectrum Elite** и
дополнительной станции **Dodo из Elite Legend 1.09**. Ядро написано на Python.
По умолчанию пиксели линий рассчитывает ручной цикл Elite.

В коде сохранены исходные таблицы моделей и целочисленные особенности выбранного
пути рендера. Комментарии и интерфейс на русском языке. Это небольшой учебный
перенос рендера, а не порт всей игры.

[Результаты исследования по всем моделям, разборы Dodo и Krait и сверка с Z80](../FINDINGS.md)

[Журнал разработки](../PROGRESS.md)

## Запуск

Рекомендуемое окружение: **Python 3.12** и pygame 2.6.1. Исходники используют
синтаксис Python 3.10+. Проверка в этом проекте выполнена на Python 3.12.

Распакуйте архив, откройте Terminal в каталоге `elite_pygame_lab`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m elite_lab
```

Если команда `python3` уже указывает на Python 3.12, её можно использовать
вместо `python3.12`. Для обычного просмотрщика требуется только pygame;
SkoolKit нужен лишь для дополнительной проверки по оригиналу.

Сразу открыть изучение линии:

```bash
python -m elite_lab --mode line
```

### Космический атлас OpenGL

В исходном наборе Elite все 20 объектов каталога висят на одной окружности. Начальный вид
показывает всё кольцо. Щёлкните по корпусу или его номеру, чтобы подлететь
ближе. Например, **09** и **12** — две Cobra Mk III с одинаковой формой и
разной обшивкой. У **00** (Coriolis) и **19** (Dodo) можно заглянуть в док.

Из каталога `elite_pygame_lab` в существующем окружении Python 3.12 выполните

```bash
.venv/bin/python -m pip install -r requirements-space.txt
.venv/bin/python -m elite_lab --mode space
```

Атлас использует OpenGL Core 3.3 или новее через ModernGL. Шесть квадратных
граней звёздного неба и текстуры панелей генерируются локально с фиксированным
зерном. При запуске их подготовка занимает несколько секунд. Видимая звезда
задаёт направление освещения и теней внутри доков и под выступами обшивки.
В наборе `elite` координаты и рёбра взяты из каталога Elite. Покраска, стекло, светящиеся
сопла и внутренности доков созданы для атласа. Выставочный масштаб сжат
так, чтобы ракета и грузовой контейнер были видны рядом со станциями.

| Управление | Действие |
| --- | --- |
| Щелчок по объекту или номеру | Осмотреть модель |
| **← / →**, затем **Enter** | Выбрать по номеру и приблизиться. В режиме осмотра стрелки сразу переключают модель |
| Перетаскивание, колесо или прокрутка трекпада | Вращать камеру и менять расстояние. **+ / −** также меняют расстояние |
| **O** или кнопка «Карта» | Вернуть общий вид кольца |
| **F**, затем **W A S D** | Свободно летать из текущей точки. **Q / E** — вниз и вверх, **Shift** — ускорение, перетаскивание — поворот взгляда |
| **H** | Скрыть или вернуть подписи и орбитальную разметку |
| **M** или кнопка «Модели» | Клавиша переключает набор, кнопка открывает список для прямого выбора |
| **T** или кнопка «Текстуры» | Переключить родные карты модели и процедурную обшивку атласа |
| **I** или кнопка «Авторы» | Показать источник выбранного корпуса, авторство, лицензию и активные текстуры |
| **Esc** | Из осмотра или полёта вернуться на карту. На карте — выйти |

Открыть отдельную модель или сохранить кадр без окна и подписей можно так

```bash
.venv/bin/python -m elite_lab --mode space --model 9
.venv/bin/python -m elite_lab --mode space --model 9 --headless --no-hud --screenshot /tmp/elite-cobra.png
```

Внеэкранный режим использует тот же GPU-рендерер и требует доступного
контекста OpenGL. [Общий вид кольца](previews/space_orbit.png) ·
[Cobra Mk III крупным планом](previews/space_cobra.png) · [Все 20 корпусов](previews/space_fleet.png).

### Приблизить Coriolis и посмотреть клиппинг

```bash
python -m elite_lab --mode clip
```

Станция открывается на глубине **Z = 640**, доком к зрителю. У выбранного
ребра № 2 исходная вершина A находится выше экрана, в (157, −27), а B видна
в (222, 51). Elite начинает с B и записывает 51 пиксель. Последний видимый
пиксель находится в (180, 1). Метки **1** и **n** показывают эти две записи.

Колесо или **+ / −** меняют дистанцию. Клавиши **[ / ]** выбирают ребро.
В инспекторе **ОБРЕЗАНО** означает, что клиппер оставил часть ребра,
**ОТСЕЧЕНО** — что он завершился до первой записи. **Enter** открывает след
работы клиппера для разбора по пикселям. [Кадр с границей окна](previews/clipping.png).

## Просмотр моделей

### 1. Модель

При запуске выбрана торговая Cobra Mk III. Клавиша **3** открывает каталог.
У каждой модели можно вращать каркас и рассматривать отобранные для рисования рёбра.
Справа — выбранное ребро, его вершины, две связанные грани, их флаги,
порог дальности и причина принятого решения. Цветом выделены реальные пиксели
этого ребра, полученные тем же алгоритмом.

| Управление | Действие |
|---|---|
| Стрелки | Повернуть корабль |
| Q / E | Изменить крен |
| Колесо мыши или + / − | Изменить расстояние |
| [ / ] | Выбрать предыдущее / следующее ребро |
| Enter | Перенести видимое выбранное ребро в пошаговый режим |
| Space | Включить / остановить автоповорот |
| F | Переключить тест видимости граней и остановить автоповорот в текущем ракурсе |
| P | Показать ракурс выбранной модели, в котором тесты дают разные пиксели |

### 2. Шаги линии

Ручная функция `trace_line()` выдаёт последовательность пиксельных шагов.
Просмотрщик воспроизводит эту последовательность: для каждого шага выполняется
ручная запись бита. Справа видны координаты, исходный адрес Spectrum,
битовая маска, значение накопителя E до/после сложения и перенос.

| Управление | Действие |
|---|---|
| → или N | Выполнить одну следующую запись пикселя |
| ← | Вернуться на один шаг |
| Space | Автоматически выполнять шаги |
| Home / R | Вернуться к началу |
| End | Показать весь отрезок |
| Мышь | Перетащить ближайший конец A или B |
| P | Переключить учебные примеры |
| G | Показать / скрыть сетку |

На клавиатуре Mac без отдельных Home/End можно использовать **Fn+← / Fn+→**;
сброс также доступен клавишей R.

Увеличенная сетка показывает окрестность текущего пикселя. Жёлтая клетка —
последний записанный пиксель. `carry` в панели относится к переходу **от него
к следующему**. На последнем пикселе исходный код возвращается раньше
прибавления slope, поэтому значение E остаётся прежним.

### Сравнение тестов видимости

**F** работает у всех 19 моделей с гранями. Кассетные модели открываются
с оригинальным тестом Elite, Dodo — с тестом через вершину. Просмотрщик
запоминает выбор для каждой модели до закрытия окна. Для Splinter оба теста
возвращают одинаковый результат при любом ракурсе, поскольку проверять грани
у этой модели не требуется.

Нажмите **P**, чтобы открыть проверенный пример, затем **F**, чтобы сравнить
его при тех же углах, расстоянии и выбранном ребре. Например,
`python -m elite_lab --mode faces --model 10` открывает торговый Python на
Z = 384 с выбранным ребром 14. Исходный тест показывает грань 9. При переходе
на вершину исчезают рёбра 4, 14 и 22, и меняются 170 пикселей.

В обоих тестах используются одна табличная нормаль и одна арифметика Elite.
Меняется точка для вычисления направления взгляда. В исходном тесте её задаёт
сама нормаль с учётом масштаба модели. Во втором тесте берётся первая вершина
первого ребра между этой гранью и соседней. У некоторых каркасов, в том числе
у Python, табличная нормаль лишь приближённо перпендикулярна поверхности.

Проверены 56 ориентаций на доступных для каждой модели дистанциях от ближнего
предела до Z = 6000. Из 13 384 пар кадров в 1 034 изменились флаги и набор
отобранных рёбер, а в 889 — пиксели после клиппинга и растеризации.
В [результатах по каждой модели](face_comparison.json) сохранены числа случаев,
углы yaw/pitch/roll, глубина Z и номера рёбер для клавиши **P**.
Повторить проверку можно командой
`python tools/compare_face_tests.py --output face_comparison.json`.

## С какого файла начать

1. **`elite_lab/raster.py`**, функция `trace_line()` — главный учебный пример.
   Здесь явно видны ведущая ось, приращение, восьмибитный накопитель, перенос
   и изменение координат. В **`elite_lab/clipping.py`** функция `prepare_line()`
   готовит начальный пиксель и счётчик, а `slope_increment()` выполняет исходное деление.
2. **`elite_lab/framebuffer.py`**, функция `set_pixel()` — ручная запись бита:
   выбор байта, маски и операция OR.
3. **`elite_lab/renderer.py`** — проверка граней, выбор вершин, проекция и
   выбор рёбер. Каждый этап привязан к адресу оригинальной процедуры.
4. **`elite_lab/arithmetic.py`** — численные особенности оригинала:
   знак-модуль, отрицательный ноль, табличное умножение и деление.
5. **`elite_lab/model.py`** — чтение заголовков, вершин, рёбер и нормалей из исходного каталога.

`viewer.py` содержит только интерфейс и воспроизведение вычисленных пикселей.
`controls.py` переводит удобные углы UI в квантованные nose/roof; это современное
управление входной позой, а не воспроизведение игровой физики.

## Как именно рисуется линия

Для внутреннего экранного отрезка алгоритм имеет следующую структуру:

```python
E = 128
for each_pixel:
    framebuffer[byte_address] |= pixel_mask
    if this_is_the_last_pixel:
        return

    total = E + slope
    carry = total >= 256
    E = total & 255

    step_along_major_axis()
    if carry:
        step_along_minor_axis()
```

Это схема; полная исполняемая реализация находится в `raster.py`.
В ней есть важные особенности конкретно Elite:

- Начальное значение E — **128**.
- Для обычного случая `slope` соответствует восьмибитной дроби minor/major.
  Сохраняется оригинальный алгоритм деления, в том числе особые входы.
- Ведущая ось выбирается сравнением **`dx >> 1` и `dy >> 1`**. Поэтому при
  `dx=4, dy=5` выбирается X, хотя точное сравнение выбрало бы Y.
- Число записей — `max(major_delta, 1)`. Конец B обычно не записывается.
- Совпавшие концы дают один пиксель.
- При равных приращениях slope равен 255, а не 256.
- В обычном режиме корабля бит добавляется через **OR**. Вспомогательная
  `apply_trace()` также позволяет отдельно исследовать XOR; это не удаление
  перекрытых поверхностями участков.

### Два показательных примера

`(100,50) → (110,55)`:

- `dx=10`, `dy=5`, ведущая X, slope=128;
- пиксели `(100,50), (101,51), (102,51), (103,52), …, (109,55)`;
- конечная точка `(110,55)` не записывается.

`(100,50) → (104,55)`:

- сравниваются 2 и 2, поэтому ведущая X;
- slope=255, четыре пикселя;
- результат `(100,50), (101,51), (102,52), (103,53)`.

Оба примера включены в клавишу **P** и проверены исполнением оригинальных
инструкций. Необычный второй результат сохранён намеренно.

## Что перенесено и где границы версии

Просмотрщик использует фронтальный вид, центр объекта `(0, 0, z)`, исходные
проверки граней, проекцию и отбор рёбер. Клиппер `$B044` принимает восьмибитные
модули X/Y и их отдельные знаки. При `xmag < 128` и `ymag < 64` у обоих концов
работает прежняя внутренняя ветвь. Если один конец снаружи, обход начинается
с внутреннего. Для двух внешних концов выбор зависит от таблицы `$AFF0` и
сравнения наклонов к углам окна. Процедуры `$B274/$B2B2` находят вход,
а `$B362` определяет число записей до выхода. Пиксельный цикл использует
наклон, рассчитанный до обрезки.

Из-за округления запись может закончиться за один или несколько пикселей до
границы. Для некоторых почти касательных отрезков адрес, наоборот, переходит
в соседнюю строку или за пределы видеобуфера. Трасса сохраняет адреса и маски
таких записей. На картинке видны только записи в диапазоне `$C000..$CFFF`.

### Как выбирается точность проекции

При Z ≥ 768 используется обычная ветвь `$AB73`. При Z < 768 (LOD < 4)
процедура `$ACA2` проверяет каждую отобранную вершину отдельно. Она объединяет
модули трёх координат через OR и считает ведущие нулевые биты. Если старший
бит занят, проекция идёт через `$AB73` с нулевыми остатками. Это верно для
всех вершин Coriolis и Dodo на любой доступной дистанции.

При ненулевом сдвиге `$AA2B` масштабирует координаты перед табличным умножением.
После сложения частичных произведений биты, вытесненные обратным сдвигом,
попадают в дробный байт оси. Процедура `$AB4F` учитывает остаток и знак
при переносе вершины в систему камеры. `$AC69` нормализует и делимое, и делитель
вместе с их дробными байтами. Полученные трёхбайтовые проекции поступают в
тот же клиппер `$B044`.
[Листинг поворота](https://github.com/Rasmus-M/elite-skoolkit/blob/66ee08efb2aceddbd67d5003c28fed3477b34850/src/elite.skool#L14080-L14205) · [Выбор ветви и проекция](https://github.com/Rasmus-M/elite-skoolkit/blob/66ee08efb2aceddbd67d5003c28fed3477b34850/src/elite.skool#L14518-L14682).

В просмотрщике верхняя граница Z равна 6000. Ближний предел выбран по размеру
модели, чтобы камера оставалась снаружи при вращении. У обеих станций он равен
256, у Viper — 128, у спасательной капсулы — 64, у контейнера — 32.
Между Z = 256 и ближним пределом шаг колеса или клавиш уменьшается со 128 до 16.

Геометрическое скрытие середины ребра другими частями корабля не добавлялось:
в изученном оригинальном пути такого этапа нет. Ребро, прошедшее проверки,
передаётся на рисование целиком.

## Проверка по настоящему Z80-коду

`reference.py` выполняет исходные машинные инструкции в SkoolKit 10.1.
Они используются только в проверке, **не внутри Python-рендерера**.

```bash
python -m pip install -r requirements-verify.txt
python tools/verify_reference.py --lines 1000 --poses 128 --output validation.json
```

Параметры задают число случайных случаев, к которым добавляются направленные
проверки. Включённый отчёт `validation.json` фиксирует успешный прогон:

- 2056 внутренних линий и 133675 пиксельных записей.
- 3872 отрезка с внешними концами, из них 1780 полностью отсечены.
  Для всех 250874 записей совпали адреса и битовые маски.
- По всем 20 моделям проверено 6606 поз, из них 3006 на ближних дистанциях.
  Кадры Dodo с исходным тестом Elite сверены в 324 положениях. Для всех
  19 сохранённых ракурсов сравнения отдельно проверяются опорные вершины,
  изменившиеся флаги, рёбра и число отличающихся от Z80-кадра пикселей.

Совпали адреса и маски записей, значения накопителя ошибки, флаги граней,
сдвиг и все три дробных байта каждой спроецированной вершины, байты проекций, набор выбранных рёбер, последовательности пикселей
каждого ребра и **все 4096 байт итогового буфера**.

Проверены знаковые комбинации и отрицательный ноль, разные направления,
вырожденные линии, особый выбор ведущей оси, границы дальностных порогов и
случайные ориентации. Это воспроизводимое дифференциальное тестирование
заявленного диапазона, а не формальное доказательство для всех входов.

В `reference_data/renderer_blocks.json` находятся только необходимые блоки:
**4439 исходных байт**, их SHA-256 и происхождение. Код и модель побайтно
сверены с полезной нагрузкой TAP из того же закреплённого репозитория.
Таблица квадратов взята из снимка памяти после инициализации. Полного образа
игры в проекте нет.

Файл `reference_data/blueprints.bin` занимает 3619 байт и содержит весь диапазон
`$6180..$6FA2` включительно. Он извлечён из листинга и побайтно сверен
с блоком по смещению 8798 в файле `tape/elite.tap` той же ревизии.
SHA-256 блока — `48be3831b28ae05412f749c812eb2e34d963d8cd71eabd329ac65d6c20c015d9`.
[Исходный листинг](https://github.com/Rasmus-M/elite-skoolkit/blob/66ee08efb2aceddbd67d5003c28fed3477b34850/src/elite.skool#L587-L1674) · [Кассета](https://github.com/Rasmus-M/elite-skoolkit/blob/66ee08efb2aceddbd67d5003c28fed3477b34850/tape/elite.tap).

## Снимки интерфейса и проверка без окна

В каталоге `previews` лежат кадры всех трёх вкладок. Получить их самостоятельно:

```bash
python -m elite_lab --headless --screenshot previews/ship.png
python -m elite_lab --headless --mode line --screenshot previews/line.png
python -m elite_lab --headless --mode catalog --screenshot previews/catalog.png
python -m elite_lab --headless --mode clip --screenshot previews/clipping.png
python -m elite_lab --headless --mode clip --model 19 --screenshot previews/dodo_clipping.png
```

На macOS с Apple Silicon модель и пошаговый разбор линии проверены в нативном окне pygame.
Для исходной позы Enter открывает ребро № 7. После двух нажатий → инспектор
показывает пиксель (97, 59), адрес $C3EC, маску 01000000 и перенос из суммы
206 + 78. Перетаскивание концов, масштаб, анимация и изменение размера окна
дополнительно проверены через программный SDL-драйвер.
